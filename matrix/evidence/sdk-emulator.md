# Evidence — sdk-emulator (runtime validation platform)

The Google SDK emulator is Anvil's **runtime validation platform** — the
environment where userland artifacts are proven to execute on a real Android
system. It is NOT a device family and has no row in `matrix/devices/`: it is
virtual hardware with a stock goldfish kernel, and nothing about its posture
transfers to shipping devices. This page cites what it can and cannot
validate, and the platform defects the validation campaign surfaced.

## Platform identity (cited from committed dumps)

- `emulator-image`: `system-images;android-36.1;google_apis;x86_64`, build
  fingerprint `google/sdk_gphone64_x86_64/emu64xa:16/BE4B.251210.005/14574095:userdebug/dev-keys`,
  kernel `6.12.38-android16-5-gbb9513914902`, security patch `2026-01-05`,
  SELinux Enforcing, `kptr_restrict=2`, `mmap_min_addr=32768`. Source:
  `results/emulator/*/posture-*.json` (generated by `emulator/posture.sh`;
  dump script committed alongside).
- `emulator-not-a-kernel-validation`: the emulator boots the stock
  `kernel-ranchu` shipped inside the system image. **No Anvil kernel fragment
  is validated by anything in `results/emulator/`** — fragment validation
  requires a bootable custom kernel (Cuttlefish + android-common build) and
  is not claimed anywhere in this repository.

## What the emulator validated (committed runs)

- `hmalloc-interposed`: GrapheneOS/hardened_malloc at the pinned SHA, built
  with the NDK against bionic, loaded via `LD_PRELOAD` into a live Android
  process; verified malloc/calloc/realloc/aligned/posix_memalign traffic
  served by the allocator via the stats-gated `mallinfo_narenas` probe
  (narenas=5; stock scudo cannot answer that symbol). Source:
  `results/emulator/*/smoke-*.json` (`interposed.pass=true`),
  `results/emulator/*/interposed.out`.
- `hmalloc-wrap-demo`: a zygote-launched app (Settings) started under the
  allocator via the sanctioned `wrap.com.android.settings` property; process
  alive with `libhardened_malloc` mapped (3 regions in `/proc/<pid>/maps`).
  The harness temporarily sets permissive SELinux for this step
  (untrusted_app cannot read shell_data_file under `/data/local/tmp`) and
  restores Enforcing afterwards — both states are recorded in the run
  artifacts (`wrap.out`, `selinux_final.txt`). This is a test-harness detail
  on a debuggable image, not an integration claim: real integration ships
  the allocator inside the system image.
- `hmalloc-dlopen-refused`: bionic refuses `dlopen` of the library with the
  exact `IE access model` TLS error — which is the *expected* proof that the
  build is upstream-faithful: upstream compiles its thread-local state
  `__attribute__((tls_model("initial-exec")))` (h_malloc.c:65), and bionic
  rejects IE TLS in dlopen'ed libraries. Preload-at-exec is therefore the
  only load path, matching GrapheneOS's own deployment. Source:
  `results/emulator/*/dlopen.out`.
- `aarch64-compile-check-only`: the aarch64 artifacts prove the NDK cross
  build compiles clean; the emulator image executes x86_64 only, and no
  aarch64 runtime behavior is claimed from this milestone.

## Platform/toolchain defects found (each pinned by a committed probe)

- `ndk-emutls-recursion`: at `minSdkLevel < 29` the NDK compiles
  thread-local storage to `__emutls_get_address`; bionic's emutls allocates
  through (interposed) malloc, which recurses into hardened_malloc's own TLS
  access — infinite recursion, SIGSEGV with `Cause: stack pointer is close
  to top of stack; likely stack overflow`, backtrace cycling
  `malloc → __emutls_get_address`. Native ELF TLS for shared libraries
  requires API 29, which is therefore the build floor. Tombstone excerpt and
  build-floor decision: `results/emulator/EVIDENCE.md` §1.
- `ndk-clang19-alignas`: NDK r28 clang 19.0.1 in C23 mode silently drops
  bare `alignas` on struct members (the AST carries no alignment attribute;
  compile-time probe: `emulator/alignas_probe2.c`, which fails its
  `alignas` static_assert and passes its `_Alignas` one under every -std
  mode). In hardened_malloc this collapses `struct allocator_state`'s
  page-aligned `regions_a` to offset 328, and the init-time
  `mprotect(&regions_a, 128*24, PROT_READ|PROT_WRITE)` fails with EINVAL on
  the unaligned address — the allocator aborts on its very first allocation
  with `non-ENOMEM mprotect failure` (captured failing syscall triple:
  `addr=0x72762a20ed98 len=3072 prot=3 errno=22`,
  `results/emulator/EVIDENCE.md` §2). The build passes
  `-Dalignas=_Alignas` (labeled deviation in
  `integration/hardened_malloc/build-android.sh`, recorded in every
  artifact's `meta.json`). Upstream sources are unmodified; this may be
  worth reporting upstream for any NDK-based standalone builds.
- `bionic-setprop-empty-arg`: `adb shell setprop name ""` loses the empty
  argument and prints usage (harness detail, fixed by remote-side quoting;
  noted because the wrap-demo retry logic initially tripped on it).

## Verification paths (what would extend this milestone)

- `verification-path-cuttlefish-kernel`: booting Anvil's kernel fragments on
  a Cuttlefish device with a self-built android-common kernel would extend
  kernel-side validation from compile-only to boot-tested.
- `verification-path-real-device`: none of this transfers to hardware claims
  until the same smoke passes on a physical userdebug device with an
  Anvil-patched build — not claimed, not attempted in this milestone.
